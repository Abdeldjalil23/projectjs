# MedSuite

منصة داخلية لمركز الطب لدى سوناطراك، يستعملها الطاقم: الإدارة، الأطباء، طبيب الأسنان، والمساعد الاجتماعي.

> **حالة المشروع:** كل الصفحات تقرأ وتكتب من قاعدة بيانات Supabase، ولا توجد بيانات وهمية في الكود ولا دخول تجريبي: المنصة تحتاج مفاتيح Supabase في `.env.local` لتعمل. طلبات التكفل (المرحلة 3) تعمل كاملة: الطلب، ثم قبوله أو رفضه، ثم وثيقة برمز QR يتحقق منها الطبيب المتعاقد. التقارير (المرحلة 4) تظهر صفحتها بإشعار «مبرمج لاحقاً». النسخة الحالية للتجربة ببيانات مختلقة فقط: لا تُدخل أي بيانات عمال حقيقية.

## التقنيات

- React 18 + TypeScript + Vite
- Tailwind CSS + shadcn/ui
- React Router
- النشر: Vercel، تلقائياً من الفرع `main`، مع رابط معاينة لكل فرع

## التشغيل المحلي

يتطلب Node.js 20.19 أو أحدث (نسخة LTS).

```bash
npm install
npm run dev
```

ثم افتح `http://localhost:8080`.

قبل التشغيل الأول انسخ `.env.example` إلى `.env.local` واملأ مفتاحي Supabase (الخطوة 5 في [docs/SETUP-SUPABASE.md](docs/SETUP-SUPABASE.md)). بدون المفتاحين تعرض شاشة الدخول رسالة «الخادم غير مُعدّ» ولا يمكن الدخول.

| الأمر | الوظيفة |
| --- | --- |
| `npm run dev` | التشغيل للتطوير |
| `npm run build` | بناء نسخة النشر في `dist/` |
| `npm run preview` | تجربة نسخة النشر محلياً |
| `npm run lint` | فحص الكود |

## الخادم

خطوات إعداد Supabase (الجداول، أول حساب إدارة، المفاتيح) في [docs/SETUP-SUPABASE.md](docs/SETUP-SUPABASE.md).

لتجربة استيراد المستفيدين يوجد ملف بأسماء مختلقة: [docs/samples/beneficiaires-exemple.csv](docs/samples/beneficiaires-exemple.csv). لا تُدخل بيانات عمال حقيقية قبل الموافقة الرسمية.

## الأدوار ولوحاتها

| دور الحساب | الفضاء | اللوحة |
| --- | --- | --- |
| الإدارة | Admin | `/admin/dashboard` |
| طبيب، ممرض، أخصائي نفساني | Doctor | `/medecin/dashboard` |
| طبيب أسنان | Dentist | `/dentist/dashboard` |
| مساعد اجتماعي | Social | `/social/dashboard` |

الطبيب المتعاقد لا يحتاج حساباً: يمسح رمز QR في وثيقة التكفل فتفتح الصفحة العامة `/verify/<الرمز>`، فيرى صلاحية التكفل ويسجّل استعماله. الصفحة لا تعرض أي معلومة طبية. تفاصيل العمليات في [docs/API-CARE-REQUESTS.md](docs/API-CARE-REQUESTS.md).

اللوحة صفحة واحدة لكل الفضاءات، تعرض نشاط اليوم من قاعدة البيانات: الاستشارات، الوثائق المحررة، الزيارات المبرمجة والفائتة والمستحقة، المستفيدون، تنبيهات الأدوية، وحسابات الموظفين. كل بطاقة تظهر فقط لمن يملك صلاحيتها، وكذلك عناصر القائمة الجانبية. كل دور يُحوَّل إلى لوحته إذا حاول فتح صفحات دور آخر.

## هيكل المجلدات

```
src/
  pages/        الصفحات (beneficiaries, patient, visits, documents, medicines, admin ...)
  components/   المكوّنات (dashboard, layout, ui ...)
  context/      حالة تسجيل الدخول
  lib/          أدوات مشتركة (الأدوار، الحسابات، Supabase ...)
  i18n/         اللغات: locales/fr.ts و ar.ts و en.ts
supabase/
  migrations/   ملفات قاعدة البيانات، تُشغَّل بالترتيب
  functions/    وظائف الخادم (admin-users)
```

## اللغات

الفرنسية هي اللغة الافتراضية، مع العربية (من اليمين لليسار) والإنجليزية. يختار المستخدم لغته من زر الكرة الأرضية، وتُحفظ في حسابه.

- كل نص في الواجهة يُكتب في `src/i18n/locales/en.ts` ثم يُترجم في `fr.ts` و`ar.ts` بنفس المفتاح. TypeScript يرفض البناء إذا نقص مفتاح في أحد الملفين.
- في المكوّنات: `const { t } = useTranslation();` ثم `t('section.key')`.
- للمسافات والمواضع استعمل الأصناف المنطقية (`ms-`، `me-`، `ps-`، `pe-`، `start-`، `end-`، `text-start`) بدل `ml-`، `mr-`، `left-`، `right-`، `text-left`، حتى تنقلب تلقائياً في العربية.

## التصميم

الواجهة مستوحاة من موقع [sonatrach.com](https://sonatrach.com/fr/):

- **اللون:** برتقالي سوناطراك `#FF8500` مع الأسود والرمادي الفاتح. الألوان كلها في `src/index.css`، ويمكن لكل مستخدم اختيار لون آخر من الإعدادات.
- **الخط:** Montserrat للحروف اللاتينية (أقرب خط مجاني إلى Gotham الذي يستعمله الموقع)، وTajawal للعربية كما في الموقع. الخطان مضمّنان في التطبيق، فلا يحتاج إلى أي خدمة خارجية ويعمل على خوادم الشركة.
- **العلامات المميزة:** القائمة الجانبية داكنة والصفحة المفتوحة فيها بالبرتقالي، عناوين بحروف كبيرة تحتها خط برتقالي قصير (الصنف `title-bar`)، أرقام اللوحة على طريقة «الأرقام الرئيسية» في الموقع، وشريط من المربعات فوق التذييل وفي شاشة الدخول (الصنف `brand-pattern`).
- لا تُستعمل صور أو شعار سوناطراك الرسمي: العلامة مربع برتقالي بأيقونة، إلى أن تتوفر موافقة على استعمال الشعار.

## طريقة العمل

1. لا عمل مباشر على `main`.
2. فرع لكل مهمة انطلاقاً من `main`: `feature/...` أو `fix/...` أو `chore/...`
3. Pull Request صغير، يجرّبه الشريك على رابط معاينة Vercel.
4. الدمج بخيار **Create a merge commit**.
